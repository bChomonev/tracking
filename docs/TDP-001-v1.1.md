## 1. Executive Summary & v1.1 Architectural Pivot

### 1.1 Problem Statement
Mainstream football statistics applications (FotMob, Sofascore, Flashscore) suffer from two core product limitations:
1. **The "Context Vacuum" ("So What?" Problem):** Fans are shown 50+ isolated match statistics (e.g., `PPDA: 11.8`, `Field Tilt: 54%`, `Distance: 111.9 km`, `Box Touches: 29`) without an empirical baseline showing whether those numbers represent elite European dominance, mid-table mediocrity, or relegation-level collapse.
2. **Scoreline Deception ("Mirage Wins" & "Unlucky Losses"):** Final scorelines routinely mask structural performance. A club can win 1–0 via a low-probability strike while posting underlying work-rate and defensive transition numbers that historically lose $85\%$ of matches, or lose 1–0 while posting metrics that historically win $90\%$ of matches.

### 1.2 Product Solution
The **Performance Corridor Platform** audits every completed match and player appearance against two empirically derived, rolling 365-day boundaries calculated from Europe's Top-5 leagues:
* **The $90\%$ Win Line (Elite Ceiling):** The multi-stack statistical profile at which historical top-flight teams win $\ge 90\%$ of their matches.
* **The $85\%$ Loss Line (Collapse Floor):** The statistical boundary at which historical teams lose $\ge 85\%$ of their matches, featuring single-stack "Red Flag Vetoes."
* **Exact Historical Match Twins ($k$-NN Proof):** A deterministic 12-dimensional vector similarity lookup (`pgvector`) retrieving the 50 most statistically identical matches in European history to prove the empirical Win / Draw / Loss probability of the performance.
* **Player Effort & Passenger Audit:** A position-adjusted physical and event work-rate index combining optical tracking (Distance/90, Sprints/90) with event effort (Ball Recoveries, Duels Contested, Final-3rd Regains).

### 1.3 Why v1.1 Eliminates Live In-Game Telemetry
In v1.1, all real-time in-match polling, webhook queues, and live streaming layers are removed in favor of a **Post-Match Batch & Immutable Static Edge Architecture** executing 10 minutes after the final whistle:
1. **Mathematical Integrity:** Comparing a 25-minute live sample against a 90-minute historical benchmark introduces severe game-state noise. Waiting until full-time ensures all 12 vector dimensions reflect complete 90-minute rates and post-match audited tracking data.
2. **93% Reduction in Fixed Operating Cost:** Real-time sports API feeds cost $€1,500\text{--}€6,500/\text{month}$ because they subsidize in-play betting operators. Post-match archive feeds and scheduled batch ingestion reduce total fixed data and cloud infrastructure costs to **$< €175/\text{month}$**, lowering the business break-even point to just **8 paid subscribers**.
3. **Infinite Zero-Origin-Load Scalability:** A completed football match is immutable. Computing the entire match audit once after full-time and publishing a static JSON artifact (`2026-UCL-ATM-MUN.json`) and social receipt image (`2026-UCL-ATM-MUN.png`) to CDN Edge / Object Storage allows the platform to serve $500,000+$ concurrent post-match visitors with **zero database queries** on the read path.

## 2. Domain Model & Mathematical Specification

### 2.1 The Four Tactical Stacks (12 Core Rate Metrics)
To eliminate possession and tempo bias, raw match totals are converted into **possession-adjusted rate metrics** and grouped into four stacks:

| Stack ID | Stack Name | Core Rate Metrics (3 per Stack = 12 Vector Dimensions) | Optimal Direction |
| :--- | :--- | :--- | :--- |
| `STACK_01` | **Work Rate & Press** | 1. `distance_per_90_km` (Team distance covered per 90 mins)<br>2. `sprints_per_min_oop` (High-speed sprints per minute out of possession)<br>3. `ppda` (Opposition passes allowed per defensive action) | Higher is better<br>Higher is better<br>**Lower is better** |
| `STACK_02` | **Progression & Territory** | 4. `field_tilt_pct` (Percentage share of final-third passes)<br>5. `line_breaks_per_100_touches` (Line-breaking passes per 100 touches)<br>6. `box_touches_per_90` (Touches inside opposition penalty box) | Higher is better<br>Higher is better<br>Higher is better |
| `STACK_03` | **Attacking Execution** | 7. `npxg_created` (Non-penalty Expected Goals created)<br>8. `npxg_per_shot` (Average non-penalty shot quality)<br>9. `finishing_delta` ($\text{xGOT} - \text{npxG}$ post-shot placement boost) | Higher is better<br>Higher is better<br>Higher is better |
| `STACK_04` | **Defensive & Transition** | 10. `npxg_conceded` (Non-penalty Expected Goals conceded)<br>11. `npxga_per_shot_faced` (Opposition shot quality allowed)<br>12. `gk_goals_prevented` ($\text{PSxG Faced} - \text{Goals Conceded}$) | **Lower is better**<br>**Lower is better**<br>Higher is better |

### 2.2 Weighted Z-Score Vectorization (`halfvec(12)`)
For each metric $i \in \{1..12\}$, let $\mu_i$ and $\sigma_i$ be the rolling 365-day Top-5 European league mean and standard deviation. Every completed team performance is mapped to a 12-dimensional vector $\mathbf{v} = [z_1, z_2, \dots, z_{12}]$:

$$z_i = \text{clip}\left( d_i \cdot w_i \cdot \left( \frac{x_i - \mu_i}{\sigma_i} \right), -4.5, +4.5 \right)$$

* **Direction Multiplier ($d_i \in \{+1, -1\}$):** Set to $-1$ for `ppda`, `npxg_conceded`, and `npxga_per_shot_faced` so that positive Z-scores universally indicate stronger performance.
* **Domain Feature Weight ($w_i \in [0.8, 2.0]$):** Weights applied prior to Euclidean distance indexing so `pgvector` prioritizes high-leverage tactical dimensions:
  * `npxg_created`, `npxg_conceded`: $w = 1.8$
  * `npxg_per_shot`, `npxga_per_shot_faced`, `ppda`, `field_tilt_pct`: $w = 1.4$
  * `line_breaks_per_100_touches`, `box_touches_per_90`, `sprints_per_min_oop`: $w = 1.2$
  * `distance_per_90_km`, `finishing_delta`, `gk_goals_prevented`: $w = 1.0$

### 2.3 Dual-Boundary Corridor Math ($90\%$ Win Ceiling vs. $85\%$ Loss Floor)
Let $\mathbf{v}_{\text{best}}$ be the empirical centroid vector of the **$90\%$ Win Cohort** (historical performances with $\text{npxGD} \ge +1.60$ and positive stack alignment where teams win $\ge 90\%$ of matches) and $\mathbf{v}_{\text{worst}}$ be the centroid vector of the **$85\%$ Loss Cohort** (historical performances where teams lose $\ge 85\%$ of matches).

Using Euclidean ($L_2$) distance in $\mathbb{R}^{12}$:

$$D_{\text{best}}(\mathbf{v}) = \lVert \mathbf{v} - \mathbf{v}_{\text{best}} \rVert_2 = \sqrt{\sum_{i=1}^{12} (v_i - v_{\text{best}, i})^2}$$

$$D_{\text{worst}}(\mathbf{v}) = \lVert \mathbf{v} - \mathbf{v}_{\text{worst}} \rVert_2 = \sqrt{\sum_{i=1}^{12} (v_i - v_{\text{worst}, i})^2}$$

The bounded **Corridor Score** $C(\mathbf{v}) \in [0, 100]$ is calculated both overall ($i \in \{1..12\}$) and per individual stack ($i \in \text{Stack}_k$):

$$C(\mathbf{v}) = \left( \frac{D_{\text{worst}}(\mathbf{v})}{D_{\text{best}}(\mathbf{v}) + D_{\text{worst}}(\mathbf{v})} \right) \times 100$$

### 2.4 Diagnostic Badges & Veto Classification Rules
1. **Red Flag Stack Veto (`STACK_VETO_WARNING`):** Triggered if any individual stack score $C_k(\mathbf{v}) \le 20.0$ (indicating the team crossed the $85\%$ Loss Floor in that phase of play).
2. **Mirage Win (`MIRAGE_WIN`):** Triggered when `actual_points == 3` AND (`empirical_50_twin_win_pct <= 22.0` OR $\ge 2$ stacks trigger `STACK_VETO_WARNING`).
3. **Unlucky Loss (`UNLUCKY_LOSS`):** Triggered when `actual_points == 0` AND `empirical_50_twin_win_pct >= 75.0`.
4. **90% Win Standard (`ELITE_90_STANDARD`):** Triggered when $C(\mathbf{v}) \ge 82.0$, `empirical_50_twin_win_pct >= 88.0`, and zero stacks trigger a veto.

### 2.5 Position-Adjusted Player Effort & Passenger Index
Players playing $\ge 20$ minutes are evaluated against rolling positional cohorts (`FWD`, `MID`, `FB`, `CB`) across five effort and progression rates:
* **Physical Output ($50\%$ weight):** `distance_per_90_km`, `sprints_per_90`
* **Event Work Rate & Progression ($50\%$ weight):** `ball_recoveries_per_90`, `duels_contested_per_90`, `line_breaking_actions_per_90`
* **Classification:**
  * `WORKHORSE_ELITE`: Composite Positional Percentile $\ge 85\text{th}$
  * `STANDARD_SHIFT`: Composite Positional Percentile $20\text{th}\text{--}84\text{th}$
  * `PASSENGER_ALERT`: Composite Positional Percentile $< 15\text{th}$ (crosses the positional Passenger Floor)

## 3. Architecture Decision Records (ADRs 01–07)

* **ADR-01 (Unified Relational + Vector Storage):** Use a single **PostgreSQL 16+ instance with `pgvector`** for all relational tables, historical match statistics, and 12-dimensional vector similarity searches. External vector databases (Pinecone, Qdrant) are rejected to eliminate dual-write synchronization complexity and extra network hops.
* **ADR-02 (Mathematical Feature Vectors Over Text Embeddings):** Similarity search ($k$-NN) must use normalized mathematical feature vectors (`halfvec(12)`), never LLM text embeddings (`vector(1536)`), guaranteeing sub-2ms local SQL execution, $\$0$ embedding API cost, and exact numerical distance calculations.
* **ADR-03 (Dual-Boundary Corridor Evaluation):** All team and player metrics must be evaluated and rendered relative to both the **$90\%$ Win Ceiling** and **$85\%$ Loss Floor**, never as uncontextualized raw figures.
* **ADR-04 (Single-Tenant MVP UI, Multi-Tenant Core Schema):** All database tables, batch scripts, and static storage paths are keyed by `team_id` and `competition_id` from Day 1. Unlocking additional clubs requires zero database refactoring.
* **ADR-05 (v1.1 Updated — Compute-Once Post-Match Batch to Immutable Static Edge):** User-facing read traffic must **never** query PostgreSQL or execute live `pgvector` scans for match dashboards. When a match completes, the batch worker computes the complete `MatchAuditProjection` JSON document and uploads it to **Cloudflare R2 / AWS S3** fronted by **Cloudflare CDN** (`Cache-Control: public, max-age=31536000, immutable`).
* **ADR-06 (v1.1 Updated — Two-Pass Fixture-Aware Batch Scheduler):** Replace real-time webhook queues and streaming consumers with a lightweight scheduled batch runner triggered relative to scheduled fixture kickoff times:
  * **Pass 1 (`Kickoff + 115 mins` / ~10 mins post-FT):** Ingests full-time event and initial tracking data, computes Corridor vectors and 50 Historical Twins, generates the LLM Tactical Autopsy, and publishes the `v1` static JSON and social receipt PNG.
  * **Pass 2 (`Kickoff + 240 mins` / ~2 hours post-FT):** Runs an idempotent reconciliation pass to capture official post-match Opta/UEFA optical tracking corrections, overwrites the static artifact in R2, and issues a single CDN cache-tag purge.
* **ADR-07 (`halfvec(12)` Quantization & Declarative Partitioning):** Vector columns use 16-bit float quantization (`halfvec(12)`) indexed with `hnsw (stats_vector halfvec_l2_ops)`. Player performance tables include `position_group` partitioning keys so HNSW indexes remain compact in RAM as historical data scales across 50+ leagues.
* *(ADR-08 Deprecation Note: Server-Sent Events (SSE) and live WebSocket push layers from v1.0 are formally removed.)*

## 5. Production Database Schema (PostgreSQL 16 + `pgvector`)

```sql
-- Enable pgvector extension (v0.7.0+ required for halfvec support)
CREATE EXTENSION IF NOT EXISTS vector;

-- 1. Teams Master Table
CREATE TABLE teams (
    id SERIAL PRIMARY KEY,
    external_id VARCHAR(64) UNIQUE NOT NULL,
    name VARCHAR(120) NOT NULL,
    short_code VARCHAR(10) NOT NULL,
    league_code VARCHAR(16) NOT NULL,
    elo_rating NUMERIC(6,1) DEFAULT 1500.0,
    is_benchmark_cohort BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Matches Table
CREATE TABLE matches (
    id BIGSERIAL PRIMARY KEY,
    external_id VARCHAR(64) UNIQUE NOT NULL,
    competition_code VARCHAR(32) NOT NULL,
    season VARCHAR(12) NOT NULL,
    kickoff_utc TIMESTAMPTZ NOT NULL,
    audit_status VARCHAR(24) NOT NULL DEFAULT 'SCHEDULED', 
    -- 'SCHEDULED', 'PASS1_PUBLISHED', 'PASS2_FINALIZED'
    home_team_id INT NOT NULL REFERENCES teams(id),
    away_team_id INT NOT NULL REFERENCES teams(id),
    home_goals SMALLINT DEFAULT 0,
    away_goals SMALLINT DEFAULT 0
);

CREATE INDEX idx_matches_kickoff_status ON matches(kickoff_utc, audit_status);

-- 3. Rolling Benchmark Corridors (Versioned 365-Day Reference Lines)
CREATE TABLE benchmark_corridors (
    id SERIAL PRIMARY KEY,
    window_label VARCHAR(32) UNIQUE NOT NULL, -- e.g., '2026-27-ROLLING-365D'
    computed_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    sample_matches_count INT NOT NULL,
    metric_means JSONB NOT NULL,              -- {"distance_per_90_km": 113.5, ...}
    metric_stds JSONB NOT NULL,               -- {"distance_per_90_km": 4.2, ...}
    metric_weights JSONB NOT NULL,            -- {"npxg_created": 1.8, ...}
    win_90_ceiling_raw JSONB NOT NULL,        -- Raw threshold values for UI display
    loss_85_floor_raw JSONB NOT NULL,         -- Raw floor values for UI display
    v_best_centroid halfvec(12) NOT NULL,     -- 90% Win Line Vector Centroid
    v_worst_centroid halfvec(12) NOT NULL,    -- 85% Loss Line Vector Centroid
    is_active BOOLEAN DEFAULT TRUE
);

-- 4. Team Match Performances & 12-Dim Feature Vector Table
CREATE TABLE team_match_performances (
    id BIGSERIAL PRIMARY KEY,
    match_id BIGINT NOT NULL REFERENCES matches(id) ON DELETE CASCADE,
    team_id INT NOT NULL REFERENCES teams(id),
    opponent_id INT NOT NULL REFERENCES teams(id),
    corridor_version_id INT REFERENCES benchmark_corridors(id),
    competition_tier SMALLINT NOT NULL DEFAULT 1,
    is_home BOOLEAN NOT NULL,
    result CHAR(1) NOT NULL,                  -- 'W', 'D', 'L'
    points SMALLINT NOT NULL,                 -- 3, 1, 0

    -- Core Indexed Rate Metrics
    possession_pct NUMERIC(4,1) NOT NULL,
    distance_per_90_km NUMERIC(5,1),
    sprints_per_min_oop NUMERIC(4,2),
    ppda NUMERIC(4,1) NOT NULL,
    field_tilt_pct NUMERIC(4,1) NOT NULL,
    line_breaks_per_100_touches NUMERIC(4,2) NOT NULL,
    box_touches_per_90 NUMERIC(4,1) NOT NULL,
    npxg_created NUMERIC(4,2) NOT NULL,
    npxg_per_shot NUMERIC(4,3) NOT NULL,
    finishing_delta NUMERIC(4,2) NOT NULL,
    npxg_conceded NUMERIC(4,2) NOT NULL,
    npxga_per_shot_faced NUMERIC(4,3) NOT NULL,
    gk_goals_prevented NUMERIC(4,2) NOT NULL,

    -- Pre-Computed Corridor Scores (0.0 to 100.0)
    overall_corridor_score NUMERIC(4,1) NOT NULL,
    stack_01_work_rate_score NUMERIC(4,1) NOT NULL,
    stack_02_progression_score NUMERIC(4,1) NOT NULL,
    stack_03_attacking_score NUMERIC(4,1) NOT NULL,
    stack_04_defensive_score NUMERIC(4,1) NOT NULL,
    verdict_badge VARCHAR(32) NOT NULL,
    -- 'ELITE_90_STANDARD', 'MIRAGE_WIN', 'UNLUCKY_LOSS', 'SYSTEMIC_COLLAPSE', 'MID_TABLE_STANDARD'

    -- 12-Dimensional 16-bit Quantized Z-Score Feature Vector
    stats_vector halfvec(12) NOT NULL,
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(match_id, team_id)
);

-- HNSW Euclidean (L2) Index for Sub-2ms Historical Twin Lookups
CREATE INDEX idx_team_perf_halfvec_hnsw 
ON team_match_performances USING hnsw (stats_vector halfvec_l2_ops)
WITH (m = 16, ef_construction = 64);

-- 5. Player Match Performances & Effort Audit Table
CREATE TABLE player_match_performances (
    id BIGSERIAL PRIMARY KEY,
    match_id BIGINT NOT NULL REFERENCES matches(id) ON DELETE CASCADE,
    team_id INT NOT NULL REFERENCES teams(id),
    player_external_id VARCHAR(64) NOT NULL,
    player_name VARCHAR(120) NOT NULL,
    position_group VARCHAR(8) NOT NULL,       -- 'FWD', 'MID', 'FB', 'CB', 'GK'
    minutes_played SMALLINT NOT NULL,

    -- Physical & Event Effort Rates (Normalized per 90)
    distance_per_90_km NUMERIC(4,1),
    sprints_per_90 NUMERIC(4,1),
    top_speed_kmh NUMERIC(4,1),
    ball_recoveries_per_90 NUMERIC(4,1) NOT NULL,
    duels_contested_per_90 NUMERIC(4,1) NOT NULL,
    final_third_regains_per_90 NUMERIC(4,1) NOT NULL,
    line_breaking_actions_per_90 NUMERIC(4,1) NOT NULL,

    -- Position-Adjusted Corridor Evaluation
    effort_corridor_score NUMERIC(4,1) NOT NULL,
    progression_corridor_score NUMERIC(4,1) NOT NULL,
    audit_status VARCHAR(24) NOT NULL,        -- 'WORKHORSE_ELITE', 'STANDARD_SHIFT', 'PASSENGER_ALERT'
    UNIQUE(match_id, player_external_id)
);

CREATE INDEX idx_player_perf_match_team ON player_match_performances(match_id, team_id);

-- 6. Immutable Static Snapshot Registry
CREATE TABLE match_audit_snapshots (
    match_id BIGINT NOT NULL REFERENCES matches(id) ON DELETE CASCADE,
    team_id INT NOT NULL REFERENCES teams(id),
    pass_number SMALLINT NOT NULL DEFAULT 1,  -- 1 = FT+10m, 2 = FT+2h Final
    r2_json_url TEXT NOT NULL,
    r2_receipt_png_url TEXT NOT NULL,
    payload JSONB NOT NULL,
    published_at TIMESTAMPTZ DEFAULT NOW(),
    PRIMARY KEY (match_id, team_id)
);
```
